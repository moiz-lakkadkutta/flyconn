Every number below was pulled live from the GitHub REST API (`gh api`), PyPI JSON API, the neuPrint HTTP API, or the linked page on that date; anything I could not confirm is marked UNVERIFIED.

## 2. neuprint-python

- Repo: https://github.com/connectome-neuprint/neuprint-python  ·  PyPI: https://pypi.org/project/neuprint-python/  ·  Docs: http://connectome-neuprint.github.io/neuprint-python/docs/
- **What it does.** Thin Python client over the neuPrint HTTP/Cypher API: `Client(server, dataset, token)`, `NeuronCriteria`, `fetch_neurons`, `fetch_adjacencies`, `fetch_synapses`, `fetch_synapse_connections`, `fetch_paths`, skeleton fetch. Returns pandas DataFrames. Since 0.5.2 it can optionally pull results as Arrow IPC (`fetch_custom(..., use_arrow=...)`, `/api/custom/arrow`, requires neuPrint server >= 1.7.3) (changelog: https://github.com/connectome-neuprint/neuprint-python/blob/master/docs/source/changelog.rst).
- **License:** BSD-3-Clause (GitHub API `license.spdx_id`).
- **Versions:** PyPI 0.6.3 uploaded 2026-07-20; 45 releases; `requires_python >=3.9`; deps `requests, pandas, tqdm, ujson, asciitree, scipy, networkx, packaging, pyarrow`.
- **Maintenance:** last commit 2026-07-20 (`d89e624 changelog update for release 0.6.3`); 18 open issues, 1 open PR; 7 contributors; 81 stars. **No GitHub Actions test workflow** (the only workflow is the dynamic `pages-build-deployment`); tests exist in `neuprint/tests/` (`test_arrow_endpoint.py, test_client.py, test_neuroncriteria.py, test_queries.py, test_skeleton.py, test_utils.py`) and are run via a pixi task.
- **API quality:** functional, well documented (Sphinx site, changelog), but **no type hints** (0 `->` annotations in `client.py`), keyword-heavy signatures, e.g.
  `fetch_adjacencies(sources=None, targets=None, rois=None, min_roi_weight=1, min_total_weight=1, include_nonprimary=False, export_dir=None, batch_size=200, properties=['type','instance'], *, weight_props='all', omit_rois=False, threads=4, client=None)` (https://github.com/connectome-neuprint/neuprint-python/blob/master/neuprint/queries/connectivity.py). 0.6.3 changed default behaviour (`weight_props='all'` adds extra weight columns) — a minor API-stability flag.
- **MaleCNS support (verified live 2026-09-26):**
  - `curl https://neuprint.janelia.org/api/dbmeta/datasets` lists `male-cns:v0.9` (last-mod 2025-06-18) and **`male-cns:v1.0`** (last-mod 2026-03-28, segment-property update 2026-06-08), alongside `hemibrain:v1.2.1`, `manc:v1.0/v1.2.1/v1.2.3`, `optic-lobe:v1.0.1/v1.1`, `mushroombody`.
  - A second server `https://neuprint-cns.janelia.org` lists `flywire-fafb:v783b`, `hemibrain:v1.2.2`, `male-cns:v0.9`, `male-cns:v1.0`, `manc:v1.2.4` but returned **HTTP 401** to an unauthenticated custom query.
  - An unauthenticated `POST https://neuprint.janelia.org/api/custom/custom` with `{"cypher":"MATCH (n:Neuron) RETURN count(n)","dataset":"male-cns:v1.0"}` returned HTTP 200 and `{"data":[[176422]]}` — so the public server itself did not require a token for that read.
  - **However, `neuprint-python` refuses to construct a client without a token**: `Client.__init__(self, server, dataset=None, token=None, verify=True, progress=True)` does `token = os.environ.get('NEUPRINT_APPLICATION_CREDENTIALS')` and then `raise RuntimeError("No token provided. Please provide one or set NEUPRINT_APPLICATION_CREDENTIALS")` (https://github.com/connectome-neuprint/neuprint-python/blob/master/neuprint/client.py, lines ~408-445). So in practice: **yes it works against MaleCNS (`server="https://neuprint.janelia.org"`, `dataset="male-cns:v1.0"`), and yes it requires a token** (free account at neuprint.janelia.org). The MaleCNS download page also states a token is required for neuPrint (https://male-cns.janelia.org/download/).
- **Gap vs flyconn:** online-only (no offline/cache layer), token mandatory, per-query Cypher round-trips (a whole-CNS adjacency pull is slow vs the 1.1 GB feather export), no NT sampling, no uncertainty, no cross-dataset harmonization, no type hints. Not needed for bulk ingest since Janelia ships flat feather files (§9).
- **Verdict: depend-on (thin, optional).** Use it for targeted live queries/ROI breakdowns and skeletons; use the official feather exports for the bulk graph.

## 3. caveclient

- Repo: https://github.com/CAVEconnectome/CAVEclient  ·  PyPI: https://pypi.org/project/caveclient/  ·  Docs: https://caveconnectome.github.io/CAVEclient/
- **What it does.** Client for the Connectome Annotation Versioning Engine microservices: materialization (versioned annotation/synapse tables), chunkedgraph (root-ID lookups, lineage), annotation, info, skeleton, L2-cache services. Dataset is chosen by `datastack_name`; FlyWire (`flywire_fafb_public`, `flywire_fafb_production`), BANC (`brain_and_nerve_cord`) and FANC are all CAVE datastacks (FlyWire datastack names verified in fafbseg's `FLYWIRE_DATASETS`/CAVE map: https://github.com/navis-org/fafbseg-py/blob/master/fafbseg/flywire/utils.py lines 50-71; BANC datastack `brain_and_nerve_cord` appears in the BANC neuroglancer skeleton URL in the tutorial README).
- **License:** MIT (`license_expression` on PyPI and GitHub).
- **Versions:** PyPI 8.2.1 uploaded 2026-07-10 (GitHub release v8.2.1 2026-07-16); 151 releases; `requires_python >=3.9`; deps `attrs, cachetools, h5py, ipython, jsonschema, networkx, numpy, packaging, pandas<3, pyarrow>=3, requests, urllib3`; optional `cloud-volume`.
- **Maintenance:** last commit 2026-07-10; 38 open issues, 21 open PRs; 14 contributors; 40 stars; CI present (`daily.yml, dev.yml, docs.yml, format.yml, release.yml`), codecov badge.
- **API quality:** mature, mkdocs site, pandas/Arrow returns, versioned materializations (good for reproducibility). Type hints partial (UNVERIFIED exhaustively). Requires a CAVE token for every datastack including FlyWire public.
- **Gap vs flyconn:** covers only CAVE-hosted datasets (FlyWire/BANC/FANC), not neuPrint ones (hemibrain/MANC/MaleCNS); online + token; raw synapse tables rather than a harmonized neuron/edge schema; no uncertainty/NT sampling.
- **Verdict: depend-on as an optional extra** (`flyconn[cave]`) for live FlyWire/BANC/FANC queries and root-ID/materialization checks; default path should be static exports.

## 4. fafbseg-py

- Repo: https://github.com/navis-org/fafbseg-py  ·  PyPI: https://pypi.org/project/fafbseg/  ·  Docs: https://fafbseg-py.readthedocs.io
- **What it does.** FlyWire/FAFB-specific toolbox on top of navis + caveclient + cloud-volume: map locations/supervoxels to root IDs, fetch meshes/skeletons, query connectivity and annotations (incl. NT predictions and the static "flywire_annotations" tables), parse/generate neuroglancer URLs, transform to other template spaces.
- **License:** GPL-3.0.
- **Versions:** PyPI 3.2.2 uploaded 2026-02-20; 52 releases; `requires_python >=3.10`; heavy deps: `caveclient>=5.4.2, cloud-volume>=8.20, navis>=1.8.0,<2.0, python-catmaid, skeletor, trimesh, fastremap, diskcache, requests-futures, inquirer, pyperclip, fuzzywuzzy`.
- **Datasets:** `FLYWIRE_DATASETS = {"production": "fly_v31", "sandbox": "fly_v26", "public": "flywire_public"}`, plus `flat_630` (`gs://flywire_v141_m630`) and `flat_783` (`gs://flywire_v141_m783`); `DEFAULT_DATASET = os.environ.get("FLYWIRE_DEFAULT_DATASET", "public")` (utils.py lines 50-87).
- **Maintenance:** last commit 2026-07-09 (`get_cave_client: avoid storing incomplete client`); 8 open issues, 2 PRs; 4 contributors; CI yes.
- **API quality:** good docs/tutorials; functional style; depends on CAVE token; version pins (`navis<2.0`) and cloud-volume make it heavyweight to install.
- **Gap vs flyconn:** FlyWire-only; online; GPL-3.0 (copyleft consideration if flyconn wants a permissive license and imports it); no MaleCNS/BANC; no graph-analysis or uncertainty layer.
- **Verdict: wrap/optional.** Import lazily only for FlyWire live helpers (root-ID updates, NT tables); do not make it a core dependency.

## 5. navis and navis-flybrains

- navis: https://github.com/navis-org/navis  ·  PyPI https://pypi.org/project/navis/  ·  Docs https://navis-org.github.io/navis/
- flybrains: https://github.com/navis-org/navis-flybrains  ·  PyPI https://pypi.org/project/flybrains/
- **What navis does.** Neuron morphology library (skeletons, meshes, dotprops, voxels), NBLAST, plotting (2D/3D, octarine/vispy/plotly/k3d), transforms, connectivity utilities, and interfaces to data sources (`navis/interfaces/`: `neuprint.py, cave_utils.py, microns.py, h01.py, allen_celltypes.py, vfb.py, neuromorpho.py, insectbrain_db.py, blender.py`, ...). It is the morphology backbone that fafbseg/cocoa/flybrains build on.
- **License:** GPL-3.0. **Versions:** PyPI 1.12.0 uploaded 2026-07-13 (release same day); `requires_python >=3.10,<4.0`; core deps include `numpy, pandas, scipy, networkx, igraph, trimesh, matplotlib, seaborn, h5py, pint, morphops, ncollpyde, molesq, rdata, skeletor, pykdtree`; many extras (`flybrains`, `cloudvolume`, `fastcore`, viewers).
- **Maintenance:** last commit 2026-09-06 (`replace trimesh's mesh processing with navis own implementation`); 31 open issues, 16 open PRs; 16 contributors; 136 stars; CI: `build-docs, publish-to-pypi, test-install, test-package, test-tutorials`.
- **MaleCNS template support:** GitHub code search for `malecns` in `navis-org/navis` returns **0** hits; MaleCNS support lives in **flybrains**: `templates.py` defines `JRCFIB2022M` ("a.k.a. 'male CNS' dataset ... whole male CNS (brain + VNC)"), `JRCFIB2022Mraw` (raw voxel units), `JRCFIB2022Mplot` (tilt-corrected for plotting), plus `JRCVNC2018M`, `MANC`, `MANCraw`, `FANC`, `BANC`, `FLYWIRE`, `FAFB14`. README changelog: "improved the `FLYWIRE/FAFB14` <-> `JRCFIB2022M` (maleCNS) transform", "added the BANC ... transforms to/from JFCR2018F and maleCNS, mirror transform" (https://github.com/navis-org/navis-flybrains#readme). cocoa's `MaleCNS` dataset sets `_flybrains_space = "JRCFIB2022Mraw"`.
- **flybrains versions/maintenance:** PyPI 0.6.3 (2025-11-17); `requires_python >=3.6`; deps `gitpython, navis>=0.6.0, numpy, pandas, h5py<=3.12.1` (note the h5py pin); last commit 2026-09-02; 6 open issues; 2 contributors; publish-only CI. Elastix/H5 transforms must be downloaded separately (`flybrains.download_jrc_transforms()` etc.).
- **API quality:** navis is the most mature Python package in this survey (docs, tutorials tested in CI, typed in places, semantic versioning). Heavy install; GPL-3.0.
- **Gap vs flyconn:** morphology-centric; no harmonized connectome schema, no signed-graph / uncertainty tooling; MaleCNS presence only as a template space, not a data connector.
- **Verdict: depend-on (optional extra `flyconn[morph]`)** for skeleton/mesh handling and template-space transforms (`JRCFIB2022M`); keep the graph core independent of navis.

## 6. cocoa (flyconnectome/cocoa)

- Repo: https://github.com/flyconnectome/cocoa (branch `main`, `cocoa/__version__.py` = `0.2.1`). Not on PyPI (`https://pypi.org/pypi/cocoa/json` is a different/nonexistent project); install is `pip install git+https://github.com/flyconnectome/cocoa.git`.
- **What it does.** "Comparative connectomics" for Python: `DataSet` classes fetch annotations + connectivity per dataset, a mapper builds a cross-dataset label graph, then `Clustering([...]).compile()` produces a joint connectivity vector (`cl.vect_`) and cosine distance matrix (`cl.dists_`) for co-clustering neurons across datasets; `extract_homogeneous_clusters()`, `plot_clustermap`, `plot_umap`, a Dash app; plus `models/` (flow connectivity, noise/upsampling models) and `Dataset.connectivity_dist`.
- **License:** GPL-3.0.
- **Datasets and versions (verified from code, `cocoa/datasets/`):** `flywire.py` (default `materialization=783`, or `"live"`; static annotations from `flyconnectome/flywire_annotations` Supplemental_file1; live via internal SeaTable), `hemibrain.py` (`_get_neuprint_hemibrain_client(version="1.2.1")`), `manc.py` (`_get_neuprint_manc_client(version="1.2.1")`, or Clio `VNC`), `malecns.py` (`MaleCNS(JaneliaDataSet)`, `_flybrains_space="JRCFIB2022Mraw"`, `_type_columns=("type","flywireType","mancType","hemibrainType")`). `datasets/__init__.py` exports only these four.
- **MaleCNS v1.0 vs v0.9 — answer:** cocoa has **no explicit v1.0 support**, but resolves the latest version dynamically. In `ds_utils.py`: `NEUPRINT_URL = "https://neuprint.janelia.org"`, `NEUPRINT_MCNS_DATASET = "male-cns:latest"`, and
  ```python
  @lru_cache
  def _parse_neuprint_dataset(dataset):
      """... Can be just a name (e.g. "male-cns") ... or "name:version" (e.g. "male-cns:v0.9") or "name:latest"."""
      ...
      available = _get_neuprint_datasets()
      versions = [d.split(":")[-1] for d in available if d.startswith(dataset)]
      ...
      if version == "latest":
          version = max(versions)
  ```
  Since the public server now lists `male-cns:v0.9` and `male-cns:v1.0`, `max(["v0.9","v1.0"])` yields `v1.0`, so **a default `cc.MaleCNS()` today targets v1.0** — by accident of string ordering, not by a v1.0-aware commit. All docstrings/README still say v0.9 (`See https://neuprint.janelia.org/?dataset=male-cns%3Av0.9`; README "4. male CNS (…male-cns%3Av0.9…)"). Relevant commits: `cec2ffb 2025-10-13 MaleCNS: switch to public neuPrint instance as default data source`, `6b01c8e 2025-10-13 malecns: actually switch to neuprint`, `d561f52 2025-07-01 MaleCNS: allow passing meta_source as {source}/{dataset}`, `92b38fc 2025-10-16 MaleCNS: fix _type_column and add hemibrain type column`. No commit mentions v1.0. The v1.0 column-name changes (if any) versus v0.9 are UNVERIFIED against cocoa's `_get_mcns_meta`.
- **BANC — answer: still a TODO on `main`.** README: "On the TO-DO list: - female adult nerve cord (FANC) - brain and nerve cord (BANC)". The unmerged branch `aedes` (last commit 2026-07-18, 16 commits ahead / 2 behind `main`; files touched include `cocoa/datasets/aedes.py`, `cocoa/datasets/cave.py`, `ds_utils.py`) adds `BANC_LIVE_COLUMNS`, `_load_live_banc_annotations(mat=None)` and `_get_banc_table()` → `ss.Table("banc_main", base="banc", read_only=True)` — i.e. BANC annotations via the lab-internal SeaTable, not the public compiled feather. `datasets/__init__.py` on `aedes` imports `aedes` (an *Aedes* mosquito dataset) but still no `banc` module. (`gh api repos/flyconnectome/cocoa/compare/main...aedes`.)
- **Cross-dataset cell typing (how it works).** `cocoa/mappers.py`: `GraphMapper(BaseMapper)` — "generates a graph consisting of `id->label(s)` and `label-labels` edges, where the latter indicates either synonyms or less granular labels. We then process that graph to maximize the number of connected components (= maximize granularity of labels) while ensuring that we maintain a mapping between all involved datasets where possible." Parameters `allow_indirect` (e.g. `MaleCNS:12345 -> mcns_group_12345 -> MaleCNS:54321 -> AOTU001 -> FlyWire:727891231`), `strict` (only intended matches, e.g. FlyWire `cell_type` ↔ maleCNS `flywire_type`), `labels="first"|"all"`. Each dataset supplies `compile_label_graph()`; MaleCNS labels come from `type` backfilled by `flywire_type, hemibrain_type, manc_type, group, instance`. `SimpleMapper` is a plain label-equality mapper. Helpers: `sanity_check_mapping`, `split_check_recursive`, `extract_mappings`.
- **API shape.**
  ```python
  hb  = cc.Hemibrain(label='hemibrain').add_neurons(['SLP001','SLP003'])
  fwl = cc.FlyWire(label='FlyWire_left', materialization=783).add_neurons([...], sides='left')
  cl  = cc.Clustering([hb, fwl, fwr]).compile(join='outer', metric='cosine', mapper=cc.GraphMapper, ...)
  cl.vect_, cl.dists_, cl.to_table(clusters=cl.extract_homogeneous_clusters())
  cc.generate_clustering(fw=None, hb=None, mcns=None, manc=None, split_lr=True, ignore_hb_l=True, live_annot=False, upstream=True, downstream=True, fw_cn_object=None, fw_materialization=783, exclude_queries=False, mcns_cn_object=None, hemibrain_cn_object=None, manc_cn_object=None, clear_caches=False)
  ```
  `MaleCNS(label="maleCNS", upstream=True, downstream=True, use_types=False, backfill_types=True, exclude_bad_types=True, exclude_autapses=True, use_sides=False, rois=None, meta_source="neuprint", exclude_queries=False, cn_object=None)`; `cn_object` accepts a `.feather` path or DataFrame "expected to come from `neuprint.fetch_adjacencies`" with columns `bodyId_pre, bodyId_post, roi, weight`.
- **Maintenance / quality:** 1 contributor, 10 stars, 2 forks; last `main` commit 2026-01-09; 1 open issue, 0 PRs; **no CI, no `tests/` directory, 0 test functions**; no docs site (3 example notebooks); `requirements.txt` includes git-only deps (`tanglegram @ git+…`, `clio-py @ git+…`), `sea-serpent` (internal SeaTable), `dash`; requires `NEUPRINT_APPLICATION_CREDENTIALS` and a CAVE token. Docstrings are extensive.
- **Gap vs flyconn:** no BANC/FANC, no explicit MaleCNS v1.0, not packaged, no tests/CI, online-only with tokens, GPL-3.0, single maintainer, no uncertainty/NT sampling/null models, no offline harmonized store.
- **Verdict: do not depend; borrow the GraphMapper idea and contribute upstream where cheap** (e.g. a PR adding a public-feather BANC dataset and v1.0 docstrings). Flyconn's cross-dataset comparison layer should re-implement label-graph matching on top of its own harmonized schema, with tests.

## 7. coconatfly / coconat / malecns / bancr (R, natverse)

- coconatfly: https://github.com/natverse/coconatfly (docs https://natverse.org/coconatfly/). coconat: https://github.com/natverse/coconat. malecns: https://github.com/natverse/malecns (the `flyconnectome/malecns` URL redirects here). bancr: https://github.com/natverse/bancr (`flyconnectome/bancr` redirects here).
- **coconatfly — what it does.** Uniform R API across fly datasets: `cf_ids('DA1_lPN', datasets=c('hemibrain','flywire'))`, `cf_meta()`, `cf_partners()`, `cf_cosine_plot()`, `match_types()`, and (new in 2026) multi-hop effective connectivity (`R/multihop.R`: "input-normalise-then-multiply approach of Schlegel et al. 2021", built on `coconat::effective_connectivity`, merged 2026-08-19 as PR #60). Keys are namespaced (`hb:1734350788`).
- **Datasets (verified, `R/datasets.R`):** `builtin_datasets = c("flywire", "malecns", "manc", "fanc", "hemibrain", "opticlobe", "banc", "yakubavnc")`, plus external datasets via `coconat::register_dataset`. README: "All datasets are either public (hemibrain, manc, malecns, flywire, opticlobe) or access can be requested … (fanc, banc)". `flywire2.R` targets `version='783.2'` synapses on the v783 segmentation. MaleCNS version comes from the `malecns` package whose README states "The default dataset is a public read only snapshot, `male-cns:v1.0`" and `choose_mcns_dataset("male-cns:v1.0")`.
- **Datasets coconatfly covers that cocoa does not:** **FANC, BANC, opticlobe (male optic lobe as a separate dataset), yakubavnc (Drosophila yakuba VNC)**, plus explicit MaleCNS v1.0 defaulting via `malecns`.

## 8. connectome_interpreter (YijieYin)

- Repo: https://github.com/YijieYin/connectome_interpreter  ·  PyPI: https://pypi.org/project/connectome-interpreter/  ·  Docs: https://connectome-interpreter.readthedocs.io/en/latest/  ·  Data prep: https://github.com/YijieYin/connectome_data_prep  ·  Preprint: https://www.biorxiv.org/content/10.1101/2025.09.29.679410
- **Paper.** "The Connectome Interpreter Toolkit", Yijie Yin, Judith Hoeller, Alexander Mathiasen, Joanna Tsang, Monique Estelle Charrier, Albert Cardona; v1 posted 2025-09-30, CC-BY 4.0 (fetched from the v1 page). The README links a v2 (`…679410v2`); v2 date UNVERIFIED (bioRxiv API returned empty to me).
- **What it implements (verified in source, `connectome_interpreter/`):**
  - *Multi-hop effective connectivity* — `compress_paths.py`: `compress_paths`, `compress_paths_signed`, `effective_conn_from_paths`, `signed_effective_conn_from_paths`, `conn_by_path_length*`, `signed_conn_by_path_length_data`, `effconn_without_loops`, `contribution_by_path_lengths*`. Matrix powers on GPU/CPU via torch, chunked, optional save-to-disk.
  - *Signed paths* — via `idx_to_sign` dicts (`add_sign(inprop, idx_to_sign)` negates rows for inhibitory neurons and transposes) and `*_signed` variants.
  - *Polysynaptic path-finding* — `path_finding.py`: `find_path_once`, `find_path_iteratively`, `find_paths_of_length(edgelist: Union[spmatrix, pd.DataFrame], inidx, outidx, target_layer_number)`, `enumerate_paths`, `create_layered_positions`, `remove_excess_neurons`; plotting `plot_paths`, `plot_layered_paths`.
  - *Differentiable activation model* — `activation_maximisation.py`: `_NetworkBase(nn.Module)` → `LinearNetwork`, `MultilayeredNetwork` (rate model, activation `tanh(relu(slope*x+bias))`, per-group slopes/biases/taus, divisive normalisation, `output_clamp_max`, `output_rectify`), `train_model`, `training_mode`.
  - *Activation maximisation / gradients* — `activation_maximisation(model, target_activations: TargetActivation, input_tensor=None, num_iterations=50, learning_rate=0.1, in_reg_lambda=0.01, out_reg_lambda=0.01, custom_reg_functions=None, early_stopping=True, stopping_threshold=1e-5, n_runs=10, ..., device=None, wandb=False, seed=None, normalize_gradients=False, quiet=False) -> Tuple[np.ndarray, np.ndarray, List[float], List[float], List[float], List[np.ndarray]]`, `saliency`, `get_gradients`, `guess_optimal_stimulus`.
  - Extras: `external_map.py`/`external_paths.py`, `get_ngl_link`, hex/Mollweide receptive-field plots, bundled odour-response datasets (`data/DoOR`, `Hallem_Carlson_2006`, `Dweck2018`, `Badel2016`, ...).
- **Input format — does it take an arbitrary scipy sparse matrix + metadata df? Yes.** `docs/your_own_data.rst`: "you need the following two components: a connectivity matrix in sparse form (pre in rows, post in columns), and a dataframe containing meta-information (e.g. neuron id, cell type etc.) corresponding to the indices in the connectivity matrix." Values are expected to be *input proportions* ("the number of synapses from A to B / the total number of post-synapses B has"), float32, `scipy.sparse.coo_matrix`/`csc`. Exact signatures:

  `_NetworkBase.__init__` converts `np.ndarray` → `coo_matrix` and any `scipy.sparse.spmatrix` → torch sparse (`scipy_sparse_to_pytorch`). ## 10. Direct answers to the three specific questions

1. **Does connectome_interpreter accept an arbitrary scipy sparse matrix + metadata dataframe so we can feed it MaleCNS?** Yes. Every entry point takes a `scipy.sparse.spmatrix` (or an edge-list DataFrame) plus index-keyed dicts: `compress_paths(A: spmatrix, step_number: int, ...)`, `compress_paths_signed(inprop, idx_to_sign: dict, target_layer_number: int, ...)`, `find_paths_of_length(edgelist: Union[spmatrix, pd.DataFrame], inidx, outidx, target_layer_number)`, and `_NetworkBase.__init__(self, all_weights: Union[torch.Tensor, sparse.spmatrix], sensory_indices: arrayable, ..., idx_to_group: Optional[dict] = None, ...)` (MaleCNS is already one of the tutorials' swappable datasets). Constraints: weights must be input-proportion normalised (rows sum to 1 per postsynaptic column), pre-in-rows for analysis functions, the model side wants pre-in-columns (`add_sign` transposes), float32, torch required.
2. **Does cocoa already have MaleCNS v1.0 support? Is BANC still a TODO?** No explicit v1.0 support: `NEUPRINT_MCNS_DATASET = "male-cns:latest"` with `_parse_neuprint_dataset` picking `max(versions)`, so it now silently resolves to `male-cns:v1.0` on `https://neuprint.janelia.org`; docstrings and README still cite `male-cns:v0.9`; no commit mentions v1.0 (latest `main` commit 2026-01-09 `53f8136`). BANC is still a README TODO ("On the TO-DO list: … brain and nerve cord (BANC)"); only the unmerged `aedes` branch (2026-07-18) contains BANC annotation loading, via the lab-internal SeaTable (`_get_banc_table` → `ss.Table("banc_main", base="banc")`).
3. **Does neuprint-python work against the MaleCNS neuPrint server, and does it need a token?** Yes: `Client("https://neuprint.janelia.org", dataset="male-cns:v1.0")` (also `male-cns:v0.9`); a second server `https://neuprint-cns.janelia.org` hosts `male-cns:v1.0`, `hemibrain:v1.2.2`, `manc:v1.2.4`, `flywire-fafb:v783b` but rejects anonymous queries (401). The library **always requires a token** (`RuntimeError("No token provided. Please provide one or set NEUPRINT_APPLICATION_CREDENTIALS")`), even though the public server answered an anonymous raw HTTP Cypher query for `male-cns:v1.0` on 2026-09-26.

## 11. Implications for flyconn

- Build the **harmonized data layer on the official Feather exports** (MaleCNS v1.0 `gs://flyem-male-cns/v1.0/...` CC-BY; FlyWire 783 Zenodo; BANC 888 compiled feather; hemibrain/MANC via neuPrint Arrow or the SJCABS bundles), converting once to Parquet/DuckDB with a schema aligned to `meta_data_entries.csv` (so SJCABS/bancr users can round-trip). Nothing existing does this; it is the clearest greenfield.
- Keep **neuprint-python, caveclient, fafbseg, navis/flybrains, connectome_interpreter as optional extras**, all lazily imported; the core should run offline from cached Parquet with no tokens.
- **Uncertainty propagation (NT sampling, threshold sweeps, null models) is absent from every surveyed tool** — cocoa/coconatfly use point cell-type labels; connectome_interpreter uses a fixed `idx_to_sign`. Flyconn can wrap connectome_interpreter's fast matrix-power kernels inside a sampling loop rather than re-implementing them.
- **Cross-dataset cell typing**: re-implement cocoa's `GraphMapper` (label graph → connected components) on the harmonized schema, using the `*_cell_type`/`*_match_id` columns that MaleCNS v1.0 (`flywireType, mancType, hemibrainType`) and BANC 888 (`malecns_*`, `fafb_*`, ...) already publish; validate against coconatfly outputs.
- **License**: navis, fafbseg, cocoa, flybrains, coconat* are GPL-3.0; neuprint-python (BSD-3), caveclient (MIT), connectome_interpreter (MIT). If flyconn wants a permissive license, GPL packages must stay optional plug-ins, not hard imports.
